# Jol — междугородняя доставка по пути

Первый вариант iOS MVP по приложенному ТЗ. SwiftUI, iOS 17+, Firebase Auth / Firestore / Storage / Functions / Messaging / App Check. Интерфейс на русском. Название Jol и тарифы — рабочие, их можно изменить.

Карты, поездки с несколькими посылками, телефонный вход и приватная передача позиции реализованы в коде. Онлайн-сценарии пока проверены на локальных эмуляторах; подключение проекта Firebase и проверка на двух iPhone ещё нужны. Архитектура: [авторизация и отслеживание](docs/AUTH_AND_TRACKING.md), исходный [план](docs/IMPROVEMENT_PLAN.md).

## Запуск

Если это ваш первый iOS-проект, начните с [пошаговой памятки](docs/START_HERE.md).

1. Установите полноценный Xcode 26 или новее. На текущем компьютере установлены Swift 6.3 и Xcode 26.6; первый запуск Xcode выполнен. Полноценная unsigned iOS-сборка успешно проверена в GitHub Actions. На 10 октября 2026 года на этом компьютере также установлен iOS 26.5 Simulator; приложение можно запускать на iPhone 17 Pro. Debug-сборка использует активную архитектуру симулятора, Release — все поддерживаемые архитектуры.
2. Для своего iPhone с бесплатной Personal Team используйте схему `JolParcelDemo` (только локальное демо, без Firebase, Push и App Attest); команда подписи задаётся локально в `App/Resources/LocalSigning.xcconfig`. Для обычного запуска откройте `JolParcel.xcodeproj`, выберите схему `JolParcel` и iPhone Simulator. Пакеты Firebase загрузятся через Swift Package Manager.
3. Для устройства задайте свою Apple Development Team в Signing & Capabilities и уникальный Bundle ID.
4. Без `GoogleService-Info.plist` работает локальный деморежим: выберите отправителя, создайте заказ, в профиле смените демороль на перевозчика, примите и завершите доставку. После возврата к отправителю можно оставить отзыв.
5. Для демозаказа можно ввести расстояние вручную, если MapKit не возвращает автомобильный маршрут. Фото и push требуют Firebase.

Проект Xcode уже сгенерирован. Если добавляете исходники или конфигурационный plist, выполните `python3 scripts/generate-project.py` повторно. Скрипт перезаписывает проект: изменения Team / Bundle ID в Xcode после генерации нужно применить заново.

## Что реализовано

- Телефон + пароль; SMS при регистрации и восстановлении, перенос прежнего email-аккаунта с сохранением UID. Серверный scrypt, отзыв сессий, App Check и ограничения попыток. Роли отправителя/перевозчика и профиль автомобиля.
- Создание отправления: города, точные адреса, получатель, дата, шаблоны посылки, вес/объём, комментарий, выбор фотографии через PhotosPicker.
- Автодополнение адресов, подтверждение точек на карте, автомобильный маршрут MapKit и рекомендованная цена `1000 + 8 × км + 5000 × м³`. Отправитель задаёт итоговую целую цену в тенге. Это ориентир, не финансовый расчёт или проверенная рыночная ставка.
- Каталог поездок для отправителя, предложение заказа перевозчику и принятие/отказ. Поездка принимает несколько посылок по лимиту количества и общей массы; предварительный подбор по направлению и расчёт объезда через MKDirections.
- Приватная трансляция позиции во время активной доставки с явным включением, остановкой и отображением давности. Фоновый режим реализован, испытание на физическом iPhone ещё требуется.
- Лента и история, фильтры перевозчика по маршруту и дате, переключатель своих доставок, суммы завершённых заказов. Фильтры работают на загруженном наборе; для большой базы требуется пагинация.
- Принятие на сервере Firestore-транзакцией, проверка роли и грузоподъёмности. Одна успешная заявка при конкуренции.
- Статусы `waiting → accepted → enRoute → pickedUp → delivered`; отмена до забора с причиной.
- Адреса и контакты доступны участникам; чат привязан к заказу. Лента обновляется snapshot listeners, чат — каждые 5 секунд и при отправке/обновлении экрана.
- Фото в Storage, ограничение JPEG / 5 МБ. Токены устройств и FCM-триггеры на статус и сообщение. Push содержит общий текст без адресов и сообщений.
- Отзыв отправителя после доставки. Удаление аккаунта после завершения/отмены активных заказов, повторная аутентификация и удаление связанных заказов, чатов, фото, контактов и Auth-пользователя. В `users` остаётся технический маркер `{id, deleting: true}` без имени/телефона для блокировки старых токенов.
- Локальный деморепозиторий на Swift actor с атомарной записью JSON. Он отделён от реальных аккаунтов и не синхронизируется с сервером.

## Firebase

Подробно: `docs/FIREBASE_SETUP.md`.

Создайте свой проект, добавьте iOS-приложение с совпадающим Bundle ID и положите конфигурацию в `App/Resources/GoogleService-Info.plist`. Файл исключён из Git. Перегенерируйте Xcode-проект. Включите Phone Auth (Email/Password нужен только для миграции прежних аккаунтов), Firestore, Storage, App Check; загрузите APNs-ключ. Серверные операции выполняются через Functions, правила запрещают прямую запись заказов клиентом.

Firebase не развёрнут в вашем аккаунте: учётные данные и проект не предоставлены. APNs и FCM на реальном устройстве пока не проверены; unsigned iOS simulator build прошёл в GitHub Actions. Серверные обработчики и правила проверены в локальных эмуляторах.

## Проверки

```sh
bash scripts/test-core.sh
npm ci
npm ci --prefix backend/functions
npm test
npm run test:rules
```

Нужны Swift и Node 22; для Firebase-эмуляторов Java 21+. На этой машине проверки также выполнены с Node 25.4 / Java 23. В репозитории есть lock-файлы для npm. После настройки полного Xcode команда `swift test` также прошла: 6 XCTest-тестов. В одних Command Line Tools модуль XCTest отсутствует. Исполняемая проверка `test-core.sh` проверяет то же ядро без XCTest.

## ECC

Применены навыки:

- `swift-actor-persistence`: actor, Sendable-модели, атомарная запись, изменение кеша только после успешной записи.
- `security-review`: разделение публичных и личных данных, валидация на клиенте/сервере, закрытые правила, транзакции, App Check, лимит 60 вызовов в минуту на аккаунт, повторная аутентификация удаления, тесты разных ролей.

## До публичного запуска

См. `docs/RELEASE.md` и `docs/REQUIREMENTS.md`. Нужны проверка на физическом iPhone, реальные Firebase/APNs-конфигурации, рабочие ссылки поддержки и юридических документов, тестирование TestFlight. В приложении места для ссылок предусмотрены ключами `PrivacyPolicyURL`, `TermsURL`, `SupportURL` в Info.plist.

ТЗ содержит неподтверждённые рыночные цифры и устаревшие SDK-требования. Они не используются в приложении как факты. Подготовленный код не означает готовность бизнеса и прохождение App Store Review. Автоматические платежи, проверка документов водителя, поддержка внутри приложения, оптимизация порядка остановок и казахская локализация пока не реализованы. Доступность автомобильных маршрутов Apple в нужных городах проверяется отдельно; при отказе приложение сообщает об отсутствии маршрута и не подменяет его прямым расстоянием.
