# Jol Local — бесплатная проверка на iPhone

Сервер работает на вашем Mac, приложение — на iPhone или симуляторе. Используется Firebase Local Emulator Suite: Auth, Firestore, Functions и Storage. Платёжный аккаунт и реальный Firebase-проект для этого режима не нужны.

## Каждый запуск

1. Подключите Mac и iPhone к одной доверенной домашней Wi-Fi сети.
2. Дважды нажмите **Start Jol Local.command** в папке проекта. Оставьте открывшийся терминал работающим и Mac включённым. Дождитесь `All emulators ready`.
3. Откройте `JolParcel.xcodeproj` в Xcode. Выберите схему **JolParcelLocal**, свой iPhone и нажмите ▶︎. При первом запуске разрешите доступ к локальной сети на iPhone и сетевые подключения Node/Java на Mac, если macOS спросит.
4. Откройте **Jol Local** на телефоне. Баннер сверху → **Проверить соединение**.
5. Зарегистрируйте отправителя с вымышленным номером, например `+77000000021`, и отдельным тестовым паролем от 15 символов. Код появится в форме; нажмите **Подставить тестовый код**.
6. Для перевозчика зарегистрируйте другой номер на втором устройстве или в симуляторе. Поездки, предложения и заказы общие для всех устройств, подключённых к этому Mac.

Уже установленное приложение открывается с домашнего экрана. Повторная сборка нужна после изменений кода или смены IP-адреса Mac. Скрипт запуска обновляет адрес в игнорируемом `LocalSigning.xcconfig`, сохраняя Apple Team и облачную callback-схему.

## Остановка и сохранение

В терминале сервера нажмите **Control+C один раз**, дождитесь окончания экспорта. Аккаунты, хеши тестовых паролей, заказы и файлы сохраняются в `.local-emulators/development/data` и импортируются при следующем запуске. Папка исключена из Git. Принудительное завершение процесса или выключение питания может потерять изменения после последнего экспорта.

Локальная панель администратора доступна на Mac: <http://127.0.0.1:4000>. Она позволяет просматривать тестовые данные и коды.

## Если соединение не работает

- Проверьте, что сервер ещё запущен, Mac не спит, а оба устройства в одной Wi-Fi сети. Гостевые сети иногда запрещают соединения между устройствами.
- В настройках iPhone разрешите **Jol Local → Локальная сеть**. Если адрес Mac изменился, перезапустите сервер и снова нажмите Run в Xcode.
- Сервер не запускается при занятых портах. Не закрывайте неизвестные процессы: используйте уже запущенное окно Jol или посмотрите название занятого сервиса.
- Только для симулятора можно запустить `npm run dev:local -- --host 127.0.0.1`, затем пересобрать. Для iPhone нужен частный адрес Mac, который обычный запуск определяет автоматически.

## Границы режима

- Это среда разработки с тестовыми SMS, а не подтверждение владения настоящим номером. Эмуляторы имеют административные API без авторизации. Доступ осуществляется по HTTP в локальной сети. Используйте только вымышленные данные и отдельные пароли; не открывайте порты в интернет и не запускайте сервер в публичной сети.
- Вход по телефону и паролю, отзыв сессий, роли, транзакции принятия нескольких посылок и ограничения доступа к адресам/GPS остаются настоящей логикой приложения. App Check отключён только при одновременном наличии всех локальных эмуляторов и точном проекте `demo-jol`; в облаке проверка обязательна.
- Push-уведомлений нет. Обновления заказов и GPS доступны в открытом приложении; отправка GPS в фоне использует прежний Core Location механизм и разрешение пользователя. Испытание длительной реальной поездкой ещё требуется.
- Эмулятор не запускает расписание облачной очистки и Firestore TTL автоматически. Последняя позиция скрывается правилами после двух минут, но физическое удаление истёкших данных по расписанию в этом режиме не гарантируется.
- Карты, адресный поиск и дорожные маршруты продолжают использовать Apple MapKit и интернет. Если Apple не возвращает маршрут, приложение сообщает об этом. Сервер на Mac не добавляет картографическое покрытие.
- Установку через бесплатную Apple Personal Team периодически требуется обновлять через Xcode. Публикация в App Store и облачный запуск — отдельные этапы.

## Для разработчика

Первичная подготовка: Node.js 22, Java 21+, Python 3, Xcode; затем `npm ci` и `npm ci --prefix backend/functions`.

```sh
npm run dev:local
npm test
npm run test:rules
npm run test:local
bash scripts/test-core.sh
swift test
```

`test:local` запускает отдельный временный набор эмуляторов на портах 9299/8280/5201/9399, без импорта пользовательских данных. Проверяет HTTP-транспорт регистрации, парольный вход, две принятые посылки, приватный GPS и отзыв старых сессий после восстановления пароля. `test:rules` использует стандартные порты: выполняйте его до запуска постоянного сервера или после корректной остановки.

Схема `JolParcelLocal` использует конфигурацию `DebugLocal`, Bundle ID `kz.jol.parcel.local`, отдельный Info.plist, пустые entitlements и условие компиляции `JOL_LOCAL_SERVER`. Слово `Debug` в имени конфигурации необходимо для отладочных API зависимостей Swift Package Manager. Реальный `GoogleService-Info.plist` не копируется в Local или Demo. Основная схема `JolParcel` и Release сохраняют облачные настройки; `JolParcelDemo` хранит автономные данные только на устройстве.

Сервер слушает только выбранный частный IPv4-адрес; панель, служебный hub и внутренние сервисы привязаны к loopback. Хост iOS проверяется по списку частных диапазонов. Только в Local включён отладочный флаг Firebase Functions `allowInsecureTokenAttachment`: он позволяет передать тестовую сессию на Mac по HTTP. В облачной сборке эта настройка отсутствует. Перехода на облако при недоступном Mac нет.

Официальная документация: [Authentication emulator](https://firebase.google.com/docs/emulator-suite/connect_auth), [Functions emulator](https://firebase.google.com/docs/emulator-suite/connect_functions).
